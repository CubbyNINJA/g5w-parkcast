| AIR-050 | (a) Only after AIR-048(b)'s port check passes, the receiver MUST wake `mdnsd` through the public `NsdManager` only. It MUST get the manager with `getSystemService(Context.NSD_SERVICE)`, then call `discoverServices("_airplay._tcp", NsdManager.PROTOCOL_DNS_SD, listener)`. It MUST NOT call `registerService` or `resolveService`, so nothing is ever advertised through `NsdManager`, under `ParkCast` or any other name. It MUST ignore discovery results and MUST NOT log them. It MUST NOT use root, set system properties or change any system setting to wake `mdnsd`. (b) The receiver MUST treat `mdnsd` as up only when both of these hold: `onDiscoveryStarted` arrived less than 5,000 ms after the `discoverServices` call (at exactly 5,000 ms or later it is late); and after that, a `dns_sd` client connection to `mdnsd`'s socket `/dev/socket/mdnsd` succeeded, tried every 250 ms for at most 5,000 ms. It MUST then log `mdnsd up`. (c) Next, it MUST register two services with the `dns_sd` client protocol over that socket, each with its full TXT record and with automatic renaming turned off: `_airplay._tcp` with instance name exactly `ParkCast`, and `_raop._tcp` with UxPlay's `<device id>@ParkCast`. It MUST NOT register a service before that service's TXT record is complete. It MUST NOT run UxPlay's built-in mDNS responder or any second responder. When both registrations succeed, it MUST log `advertise ok`. (d) Each of these MUST count as `advertise failed`: the manager is null, or calling it throws `SecurityException`; `onStartDiscoveryFailed` is called; `onDiscoveryStarted` does not arrive within 5,000 ms; when the 5,000 ms connect window ends, the socket is missing (`ENOENT`), permission-denied (`EACCES` or `EPERM`), refusing connections, or otherwise unreachable; a TXT record can't be built; a registration returns an error; a name conflicts. On any of them, the receiver MUST log exactly `advertise failed reason=<token> code=<n\|none>`. `<token>` MUST be, for the failures in the order listed: `null-manager`; `security-exception`; `discovery-failed`; `discovery-timeout`; `ENOENT`, `EACCES`, `EPERM` or `ECONNREFUSED` for that socket error, and `unreachable` for any other connect error; `txt-build`; `register`; `name-conflict`. `<n>` MUST be the decimal error code that `onStartDiscoveryFailed` or the `dns_sd` registration reply gave, and `none` for every other token. The receiver MUST withdraw any registration already made, and stop discovery only if `discoverServices` had returned. It MUST NOT accept connections, MUST NOT retry or fall back to another responder, and MUST take AIR-069(c)'s start-failure path. (e) If the `mdnsd` connection closes after `advertise ok`, the receiver MUST log `advertise lost`. It MUST NOT re-register, fall back or show a notice. (f) On stop, the receiver MUST withdraw both registrations and then release its `NsdManager` use with `stopServiceDiscovery`, as AIR-070 orders. (g) The first on-unit run checks whether an app holding only `INTERNET` can open `/dev/socket/mdnsd`. | OD-76, OD-148, OD-150, OD-164 (was AMB-95). ## Rationale

All changes encode OD-185 (`docs/spec/DECISIONS.md:193`), which adopts the "Requirement wording" section of `docs/spec/reviews/CLAUDE_REVIEW_s3_scenarios_2026-11-16.md:180-206`. Each row was rebuilt by script from `docs/spec/REQUIREMENTS.md` (AIR-048:58, AIR-050:60, AIR-053:63, AIR-056:66, AIR-058:68, AIR-069:79, AIR-071:81, AIR-073 to AIR-076:83-86, AIR-078 and AIR-079:88-89, AT-50:148, AT-73 and AT-74:171-172). Every old fragment was asserted to occur exactly once before it was replaced. All other text is unchanged.
- **AIR-048, AIR-053, AIR-058, AIR-079:** fixed log texts, so tests can match them exactly.
- **AIR-050 and AT-50:** reason tokens and `code=`; exactly 5,000 ms counts as late; `EPERM` added; `unreachable` covers any other connect error; discovery is stopped only if `discoverServices` had returned.
- **AIR-056(f):** the decoder is created when the H.264 codec configuration arrives, not before.
- **AIR-069(f):** fixed check order; both checks always run.
- **AIR-071:** fixed reason vocabularies and the uptime prefix (g), which AIR-076(h) relies on.
- **AIR-073(g) and AT-73:** header-line, byte-range and hex and base64 run rules, with boundaries at 31/32 hex characters and 43/44 base64 characters.
- **AIR-074(d) and AT-74:** keep-existing covers files that appear during the run; a folder that already exists before the run stays under (g).
- **AIR-075(e), (f):** `Checklist:` is the last line; the S1 field order is taken from `docs/evidence/20261115-142231-summary.md`.
- **AIR-076(h):** unparseable prefixes and UxPlay line ownership.
- **AIR-078(h):** every failed rule is reported.

## Reversibility and safety

These are text-only changes to the spec. Their runtime effects are limited to log wording, the log filter, the PC evaluator and the build's package check. Nothing new is installed or changed on the PC or the unit, and no root step is added. The AIR-073(g) filter can only drop more records, so it fails safe. The AIR-076(h) unparseable-prefix rule can only stop a GO, never grant one. To revert, restore the previous rows from git.
