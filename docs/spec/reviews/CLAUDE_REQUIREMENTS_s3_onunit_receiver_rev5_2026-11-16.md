## Rationale

- **AIR-042:**
  - The spike's one patch so far is the `dlopen` name, because the unit ships `libmdnssd.so` and no `libdns_sd.so` (`docs/evidence/CROSSBUILD_SPIKE_FINDINGS.md:22-26`, `docs/evidence/RECEIVER_ENV_FINDINGS.md:13`).
  - OD-169 needs a second patch, because the HTTP server binds `INADDR_ANY` and `in6addr_any` (`CROSSBUILD_SPIKE_FINDINGS.md:50`, `docs/spec/DECISIONS.md:177`).
  - Splitting this into (d) keeps (c)'s general rule as it was.
- **AIR-044:**
  - OD-168 (`DECISIONS.md:176`) replaces OD-157's OpenSSL 3.0 (`DECISIONS.md:165`). The spike's 3.0.22 pin (`CROSSBUILD_SPIKE_FINDINGS.md:15`) now fails the build by design.
  - (c) had no room for the `dlopen` of the unit's `libmdnssd.so` that OD-164 needs (`DECISIONS.md:172`), so it is named as the one exception.
- **AIR-048, AIR-049, AIR-070, AT-49, AT-70:**
  - With `-p 35000`, TCP 35002 is unused (`CROSSBUILD_SPIKE_FINDINGS.md:33-34`). That makes five sockets, not six.
  - `wlan0` is up at 192.168.0.1/24, and the other interfaces are down (`RECEIVER_ENV_FINDINGS.md:9`).
  - The missing-address path is the AIR-069(d) "other failure" path, so it adds no new notice. AIR-076 needs no change, because such a run has no iPhone connection, which makes it INCONCLUSIVE under (c).
- **AIR-055:**
  - Stdout and stderr bypass the log callback (`CROSSBUILD_SPIKE_FINDINGS.md:48-49`).
  - Seven callbacks are called without a NULL check, and a negative return from `video_set_codec_and_size` drops the connection (`:36-40`).
  - Audio arrives compressed in `audio_process` (`:38`), so AIR-054 is unchanged.
- **AIR-072, AIR-073:**
  - At INFO the library logs IPs, the device ID, the User-Agent and the PIN. At DEBUG it logs headers, plists and key material (`CROSSBUILD_SPIKE_FINDINGS.md:45-47`).
  - The level stays debug, as AIR-071(b) needs (`docs/spec/REQUIREMENTS.md:81-82`).
  - The privacy guarantee rests on the allowlist plus (g)'s whole-record drop, never on redaction. The callback is set before `raop_init2` (`CROSSBUILD_SPIKE_FINDINGS.md:30-31`).
- **AIR-078, AT-78:**

  - AIR-074 already copies only the log directory, so its row is unchanged. AT-83 checks that.

## Reversibility and safety

- **AIR-042, AIR-044:** repository-only changes (patch files and pins). Reverted with git. Nothing changes on the unit or the PC beyond build output.
- **AIR-048, AIR-049, AIR-070:**
  - Binding only 192.168.0.1 reduces exposure compared with rev 4. Nothing is reconfigured on the unit, and the sockets close on stop (AIR-070) or when the process dies.
  - The address check only reads the interface. A missing address leaves no bound port and no registration.
- **AIR-055:** the stdio redirect affects only the receiver's own process and ends with it.
- **AIR-072, AIR-073:** these reduce what is written. A dropped record cannot be recovered, which is the intended trade.
- **AIR-078, AIR-083:**
  - AIR-083 creates one file in the receiver's app-data directory. `nemesis uninstall airplay.receiver` removes it with the APK (AIR-078(g)). The stick never holds it.
  - A corrupt key file is left as it is under AIR-083(c). Uninstalling clears it.
- **AIR-079(e):** the receiver changes nothing.
  - If CarPlay fails to reconnect after exit, the receiver is already stopped and can be removed with `nemesis uninstall airplay.receiver`.
  - No further run happens until the finding is closed. Whether uninstalling restores CarPlay is not established (see Not verified).

## Open questions

1. When `hotspot address missing` happens, the owner sees a black screen with no notice. This draft follows AIR-069(d), because AIR-069(c)'s notice covers only `port busy`, `advertise failed` and `decoder unavailable`. Should it be a fourth notice cause, showing `ParkCast can't start: hotspot address missing. Exit and try again.`? AT-48 and AIR-069 change if so.
2. A key file that exists but is unreadable or corrupt, or a key that can't be written, is drafted as a start failure with a black screen and no notice, and the file is kept. The alternative is to make a new key, which means the iPhone sees a new ParkCast. Which does the owner want, and should this cause show a notice?
