## Rationale

- **AIR-074(d), (e)**: these encode OD-181 (`docs/spec/DECISIONS.md:189`). The script places both files, and an existing file is never overwritten. Leaving the note at zero bytes keeps it a missing note under AIR-076(e) (`REQUIREMENTS.md:86`) until the owner writes in it. Writing the checklist as bare `<key>: ` lines makes every key `not recorded` under AIR-079(f), so an untouched file can never pass a check. If the blank files can't be placed, the failure stays separate from an incomplete log copy. That way it can't wrongly downgrade the log under AIR-075(b), and it still exits non-zero under (c). The clause letters (a) to (c) are kept as they were.
- **AIR-075(c)**: this encodes OD-183 (`DECISIONS.md:191`). It extends the S1 summary format (`docs/evidence/20261115-142730-summary.md`, one `Field: value` per line) with a single line. The committed summary carries only fixed keys and the three allowed values. Free text from malformed lines could hold anything, so it stays out, as the redaction rule in `specs/README.md:38-42` requires.
- **AIR-079(e)**: the template sentence is replaced by a reference to AIR-074(d) (OD-181). The decision column drops "drafted here for owner review" and the open AMB-120 note, and cites OD-182 (`DECISIONS.md:190`) for the keys. Nothing else in the row changes.
- **AT-74, AT-75, AT-79**: AT-74 adds the placement, keep-existing and placement-failure cases. AT-75 replaces "nothing else" with "plus one `Checklist:` line" and adds a check that free text stays out of the summary. AT-79 drops the `@host` stick-template check, because there is no longer a template that ships with the build. The placed file is now covered by AT-74.

## Reversibility and safety

- AIR-074(d) writes two small files to the stick only. The originals on the unit are untouched, and nothing changes on the unit. Undo it by deleting the files from the stick. Because existing files are never overwritten, a rerun into the same folder can't wipe what the owner already wrote.
- AIR-075(c) adds one line to a committed summary. The line holds only fixed keys and `yes`/`no`/`not recorded`, so it adds no personal data. Undo it by reverting the summary file.
- AIR-079 and AT-79: requirement text only. Nothing is installed on this PC or the unit.

## Open questions

1. **Layout of the `Checklist:` line.** OD-183 fixes one line with each key and its value, but not the separators. Proposal: `Checklist: parkcast listed=yes; letterboxed=no; sound on unit=not recorded; stayed behind other app=yes; nothing on cluster or hud=yes; carplay after exit=yes`, using `=` between key and value and `; ` between pairs, in AIR-079(e) order. AT-75 needs an exact layout before its scenario can assert bytes.
2. **Placement when the log copy is incomplete.** Should the script still place the blank files when the copy fails part-way? This draft doesn't say. Placing them is harmless, because the run is INCONCLUSIVE under AIR-075(b) either way, but the owner hasn't chosen.
3. **Timestamp folder that already exists.** If the `<timestamp>/` folder is already there, for example after a rerun within the same second, should the script copy into it or refuse? AIR-074(d) only guarantees that existing note and checklist files are kept. It doesn't say what happens to log files with the same names.
