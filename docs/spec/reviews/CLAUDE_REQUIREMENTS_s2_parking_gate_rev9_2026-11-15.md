## Rationale

**AIR-017.** OD-85 (AMB-67) starts the resume re-read at once rather than on the 200 ms schedule. OD-87 counts process start as a resume, so the startup read is a resume re-read, and the poll schedule restarts from each re-read's invocation. Clause (e) already keeps one call at a time, which is why the re-read waits for a pending pre-sleep call: a binder call can't be cancelled.

**AIR-019.** OD-87 names the signal and the mapping, from `docs/evidence/SLEEP_SIGNAL_FINDINGS.md`. Clause (f) forbids `registerSystemOffResponder` so the receiver can never hold up shutdown. Clause (g) and the age rule in (b) and (d) encode OD-85's discard logging (AMB-66). The OD-86 fail-safe choices made here are: a missing or non-integer extra counts as asleep; a change between two awake values, or between two asleep values, is neither sleep entry nor resume (so ADM `0`→`2`→`0` never interrupts mirroring); a sticky asleep state at process start means starting asleep, with the resume at the next awake; once a pending pre-sleep call returns, the re-read is invoked at that same clock time; a discard record carries the literal word `discarded` with either flag value. Unregistering at exit is an engineering proposal, not owner policy.

**AIR-021.** OD-85 applies discard logging and the no-age-refresh rule with either flag value. OD-87's signal and mapping drive polling stop and start with the check off too, as OD-83 already required. The gate still blocks nothing, including when the receiver starts asleep.

**AIR-023.** OD-85 accepts AMB-63: spacing on either side of `=` counts, and spaced lines compare exactly like any other occurrence (OD-80). Comparing spaced lines as whole trimmed lines is an OD-86 parsing choice. Every new outcome resolves to `true`.

**AIR-025.** OD-85 accepts AMB-64: an explicit read logs `reason=read from the file`. Leaving field order and separators to the implementation, with tests matching the literal phrases only, is an OD-86 logging choice.

**AIR-039.** OD-85 accepts AMB-65: an oversized record is dropped, and a `record too large` line naming its size goes in its place. Two OD-86 logging choices: the size counts every byte that would be written, including the line terminator; the replacement line follows normal rotation.

## Reversibility and safety

No files were edited and nothing was installed.

- AIR-017, AIR-019 and AIR-021 change only runtime polling, gate decisions and log lines. The broadcast receiver is read-only, registered at runtime and unregistered at exit. It uses no system-off responder, so it can't delay the head unit's shutdown. No getter calls are made during sleep with either flag value.
- A pre-sleep call that never returns leaves video blocked, with the check on, until the receiver restarts (fail-safe).
- With the check on, mirroring continues in ADM while Park permits it (OD-87).
- AIR-023 and AIR-025 change parsing and log text only; every new parsing outcome falls back to check-on.
- AIR-039 keeps logs within the existing limits. A dropped oversized record's content is lost; only its size survives.

## Open questions

1. **ACC receiver registration fails at start:** if registering for `ACTION_ACC_STATUS_CHANGED` throws, or returns no sticky state, sleep and resume cannot be detected. Proposal: treat this as asleep (with the check on, video stays blocked and no getter call is made; with it off, polling doesn't run, the gate blocks nothing, and the failure is logged). The alternative is to run without sleep detection, polling as if awake. This changes what the owner sees with the check on (no mirroring at all), so it needs an owner decision.
