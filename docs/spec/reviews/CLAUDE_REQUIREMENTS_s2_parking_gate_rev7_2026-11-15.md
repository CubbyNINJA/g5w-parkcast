## Rationale

**AIR-017.** OD-67 names the no-value request in clause (d) as the BCM `getGearStatusInfo` request and drops the scenario row that can't be observed. The ban on the call stays in AT-24, so AT-17 now points at that ban instead of a separate row. Clause (b) now points at AIR-019(d), because OD-74's "polling stops when the head unit sleeps" would otherwise contradict unconditional 200 ms polling.

**AIR-019.** OD-72 makes "stale" and "unavailable" one state, named "unavailable". OD-74 adds the sleep rules to clause (d) ahead of the existing resume rules. A discarded reply refreshes no age and grants no permission. The rest of the row is revision 6 verbatim.

**AIR-021.** It was the only other S2 row, with AT-21, that used "stale". OD-72 requires the "unavailable" name.

**AIR-023.** OD-68 limits trimming to the whole line and makes `video.require_park = false` unrecognised. OD-69 defines a conflict as any different value, recognised or not, and accepts identical duplicates. Clause (c) now lists the conflicting duplicate as its own fallback case, so AIR-025 can name it under OD-75. The resulting flag value, `true`, is unchanged.

**AIR-025.** OD-75 fixes the five cause names. Under OD-69 a recognised/unrecognised pair is a conflict, so its cause is "the conflicting duplicate key". OD-75's other half (a lost getter service stays lost for the rest of a scenario) is a scenario-fixture convention and changes no row.

**AIR-026.** OD-71: no persistence, so the previous value is always unknown, and the first gate change after start is a logged transition. The row is split into clauses so each can be tested on its own.

**AT-35.** OD-70 drops the sentence about reporting a partial install, because NEMESIS's installer reports installs and sits outside this package. AIR-035(c) already required nothing more, so the AIR-035 row is unchanged.

**AIR-039.** OD-73 sets rotation at 2,621,440 bytes with whole-file deletion of the older file and no trimming, replacing "when that cap is reached", which could not hold the cap without trimming.

## Reversibility and safety

No files were edited and nothing was installed.

- AIR-017 and AIR-019 change only runtime polling and video-gate decisions. During sleep the gate blocks video and makes no getter calls, which removes vehicle-service traffic. Getter access remains read-only.
- AIR-021 is a wording change only.
- AIR-023 and AIR-025 change parsing and logging; every new parsing outcome falls back to check-on, which is fail-safe.
- AIR-026 removes any need for cross-start state.
- AIR-039 keeps logs under `/data/nemesis/logs/airplay-receiver/`, within 5,242,880 bytes.

## Open questions

1. **Whitespace around `=`:** does its start record name "the unrecognised value" (drafted) or "the missing key"? Does such a line count as an occurrence of the key when checking duplicates against a well-formed line?
2. **Duplicate comparison:** are values compared exactly and case-sensitively after whole-line trimming (`false` and `False` conflict; `false` and `false ` are identical once trimmed)? Assumed, not encoded.
3. **OD-75 cause names:** must the start record contain these phrases literally, or may the log express them in another fixed form? No AIR-025/026 record format is fixed.
4. **Rotation boundary:** when a write would carry the current file past 2,621,440 bytes, should the file rotate before the write, split the record, or may it exceed the threshold provided the two together stay within 5,242,880 bytes?
5. **Sleep with the check off:** with the flag off, does polling still stop at sleep, and is video blocked during sleep by this gate?
6. **Sleep and resume signals:** which head-unit event marks sleep entry and resume? Can a call invoked before sleep that replies after resume within 200 ms serve as the resume re-read, or must the re-read be a call started after resume?
