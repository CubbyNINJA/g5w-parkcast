# S3 on-unit receiver requirements, first milestone (video only)
> Author: fresh-context Claude subagent standing in for `gpt-6-astra` under OD-78 (role file `tools/astra/roles/astra-requirements-author.md`), read-only. **Substitute for Astra.**
> Prompt: `tools/astra/prompts/S3_REQUIREMENTS.md`. Date 2026-11-16.

This is a drafted specification for owner review. It is not an owner decision. Rows marked "proposal" are my choices and need sign-off. Rows marked "fail-safe under OD-86" apply the standing rule for parsing, logging and timing edge cases. New open items start at AMB-90. The last register entry is AMB-89, and AMB-07 is still open.

## Requirements

| AIR-042 | (a) The native protocol code MUST be built from UxPlay 1.74 at commit `05b0275cb1b726592700e47a6e0307544b3d3a52`. (b) The build MUST compile only UxPlay's protocol library, and MUST NOT compile or link GStreamer, UxPlay's `renderers/` directory or `uxplay.cpp`. (c) Any change to UxPlay sources MUST be kept as a patch file in this repository and applied by the build, never as an untracked edit. | OD-141. Pinning to S1's tested commit and the patch rule are proposals. |
| AIR-043 | (a) Native code MUST be built with NDK r25c for API 19, ABI `armeabi-v7a`. (b) The APK MUST contain native libraries for `armeabi-v7a` only. (c) If the configured NDK is not r25c, the build MUST fail and name the version found, and MUST NOT fall back to another NDK on the PC. | OD-143. (b) proposal. (c) fail-safe under OD-86. |
| AIR-044 | (a) Every third-party native dependency of the protocol library MUST be built from source with the AIR-043 NDK, API and ABI, at a version pinned in this repository together with the SHA-256 of its source archive. (b) A source archive whose SHA-256 differs MUST fail the build before extraction, and no output of that dependency MUST be used. (c) Dependencies MUST be linked into the APK's own native libraries, and the receiver MUST NOT load any native library from the unit other than the platform libraries NDK API 19 exposes. | Proposal. Which dependencies and which versions: AMB-91. (b) fail-safe under OD-86. |
| AIR-045 | (a) The Android SDK MUST be installed under `C:\Android`, and every downloaded SDK package MUST have its checksum verified before use. (b) A checksum mismatch MUST stop the install, leave that archive unextracted, and leave already-installed packages unchanged. | OD-142. (b) fail-safe under OD-86. |
| AIR-046 | (a) The app MUST be an Android Gradle Plugin module in `receiver/app` with minSdk 19. It MUST depend on the Java 7 `receiver/gate` module and build its native code through CMake. (b) From a clean checkout, with the SDK, the NDK and the local signing file present, one `./gradlew` invocation MUST produce the signed APK. (c) `receiver/gate` MUST still build and pass its tests without the Android SDK. | OD-131, OD-132, OD-144. (c) is a proposal that keeps OD-66's plain-Java gate. |
| AIR-047 | (a) The signing key MUST live in the owner's user profile, and its path and passwords MUST exist only in a git-ignored local file. (b) Neither the key nor that file MUST ever be committed, and a repository check MUST fail if either is tracked or not ignored. (c) If the local file or the key is missing or unreadable, the build MUST fail and name which one, and MUST NOT produce an APK signed with a debug or generated key instead. (d) Build output MUST NOT print the passwords. | OD-145. (b) to (d) fail-safe under OD-86. |
| AIR-048 | (a) The receiver MUST listen on exactly TCP and UDP 35000, 35001 and 35002, the equivalent of UxPlay's `-p 35000`. (b) Before advertising, it MUST check that all six ports are free. (c) If any port is taken, it MUST NOT advertise or accept connections. It MUST log `port busy` with the protocol and port number, release any port it already bound, stay alive without video, and never try another port. | OD-76. (c) fail-safe under OD-86. What the owner sees: AMB-100. Verdict class: AMB-104. |
| AIR-049 | (a) The receiver MUST NOT bind, connect to or send to TCP 7000 on the unit, whether CarPlay is on or off. (b) It MUST NOT explicitly bind any local port except AIR-048's six, which rules out DiPO's TCP 5001 and 6030 and UDP 5020, 6000, 6011 and 6020. Kernel-assigned ephemeral ports for outgoing sockets are allowed. (c) It MUST NOT stop, signal or reconfigure DiPO, `mdnsd`, `hostapd`, `dnsmasq` or `wpa_supplicant`. | OD-76. Naming the DiPO ports in (b), and all of (c), are proposals. |
| AIR-050 | (a) The receiver MUST advertise through the unit's running `mdnsd`. It MUST NOT run UxPlay's built-in mDNS responder or any second responder. (b) Its service instance name MUST differ from the stock receiver's. (c) If `mdnsd` cannot be reached or registration fails, it MUST log `advertise failed` with the error code, MUST NOT accept connections, and MUST NOT fall back to another responder. (d) On stop it MUST withdraw its registration. | OD-76. The name: AMB-90. Socket compatibility: AMB-95. (c) fail-safe under OD-86. |
| AIR-051 | (a) The receiver MUST advertise a 1920×720 display at 60 fps. (b) A stream whose aspect ratio differs from the screen's MUST be shown whole and centred, with its aspect kept and black bars, and never stretched or cropped. (c) It MUST log the stream geometry it receives. | OD-92. (b) is how I read "letterboxed". (c) feeds AIR-071. |
| AIR-052 | (a) The receiver MUST advertise H.264 only and MUST NOT advertise HEVC (UxPlay's `-h265`). (b) If a session sends HEVC, its frames MUST NOT reach the decoder, and the receiver MUST log `hevc refused` and end the session. | OD-96, OD-141. (b) fail-safe under OD-86. |
| AIR-053 | (a) The receiver MUST support Screen Mirroring only. (b) It MUST refuse URL/HLS playback and DRM-protected video requests, and log each refusal by kind without the requested URL. | OD-93. Leaving the URL out of the log is a privacy proposal. |
| AIR-054 | (a) The receiver MUST NOT decode or play audio, open an `AudioTrack`, request audio focus or call `AudioManager`. (b) It MUST discard incoming audio data without writing it to any log or file. (c) It MAY log the announced audio format. | OD-139, OD-94. AIR-022 still applies. (c) follows AIR-008(b). What the owner hears: AMB-101. |
| AIR-055 | (a) Native code MUST pass to Java only session start and end events, codec-configuration data, H.264 access units with their timestamps, stream geometry, and log records. (b) Native code MUST NOT call Android framework, vehicle, audio or display APIs. (c) Java MUST call native code only to start it, stop it and read its status. (d) Every native log record MUST go through AIR-073's filter before any write. (e) No native callback MUST reach Java after stop returns. | OD-141. Every clause is a proposal that defines the boundary. |
| AIR-056 | (a) The decoder MUST be created by the name `OMX.TCC.avcdec`, with no codec-list lookup and no fallback to any other decoder, software ones included. (b) It MUST render to the receiver activity's own Surface. (c) If creating or configuring it fails, the receiver MUST log `decoder unavailable` with the exception class, show no video, end the session, and not crash. (d) If the decoder errors mid-session, the receiver MUST release it, log `decoder error`, end the session, and not retry within that session. | OD-96, OD-141. (c) and (d) fail-safe under OD-86. |
| AIR-057 | (a) Every decoded output buffer MUST pass the S2 gate's per-frame decision before it can appear. (b) A permitted buffer MUST be released with render, and a blocked buffer released without render. (c) When the gate blocks, the displayed image, including a frozen last frame, MUST be cleared within AIR-018's 250 ms. (d) While blocked, the receiver MUST keep the iPhone connection and keep draining the decoder, so that no backlog appears when video returns. | OD-140, OD-23, OD-48, AIR-018, AIR-037. Mapping `Display.show`/`clear` onto `releaseOutputBuffer(render)` plus a black cover is a proposal. |
| AIR-058 | (a) The Park getter MUST call `VehicleInfoManager.getGearPStatus()` on a worker thread, one call at a time, every 200 ms, with a 200 ms timeout. (b) It MUST NOT call the BCM gear-status method or anything else that sends `REQ_GEAR_STATUS`. (c) A `SecurityException`, a binder failure, a missing class or a timeout MUST reach the gate as "unavailable" and be logged with the exception class. | OD-61, OD-62, AIR-017, AIR-019, AIR-024. (c) fail-safe under OD-86. Access as an app: AMB-98. |
| AIR-059 | (a) ACC state MUST come from the sticky ACC broadcast, registered without a permission on a worker thread with a main-looper Handler. (b) The receiver MUST NOT call `registerSystemOffResponder` or micom power transaction 14. (c) A registration failure MUST follow AIR-019(h) and (i). | AIR-019, AIR-021. The S2_GATE port table. |
| AIR-060 | (a) The `com.hkmc.intent.action.REVERSE_ON` receiver MUST be registered in code, synchronously in `onCreate`, and not declared in the manifest. (b) The receiver MUST treat that broadcast as not sticky, and MUST NOT use `REVERSE_OFF` or `isRearViewOn`. | OD-136, AIR-041. The S2_GATE port table. |
| AIR-061 | (a) Notices MUST be built with `Toast.makeText(...).getView()` and added through `WindowManager` as `TYPE_TOAST`, without `SYSTEM_ALERT_WINDOW`. (b) If adding a notice fails, that MUST be logged and MUST NOT change the video decision. (c) No notice MUST be shown while the receiver is covered. | AIR-040, AIR-041, OD-117, OD-120. (b) fail-safe under OD-86. |
| AIR-062 | (a) The receiver MUST write its logs to `/data/nemesis/logs/airplay-receiver/`, under AIR-039's rotation and cap. (b) If that directory is missing or the app cannot write to it, that is a logging failure under AIR-040. The receiver MUST NOT create, chmod or chown anything outside the directory to work around it. | AIR-039, AIR-040. Who creates the directory, and with what owner, before S4 exists: AMB-93. |
| AIR-063 | (a) The receiver MUST read `video.require_park` from `/data/nemesis/apps/<id>/config/receiver.conf` under AIR-023. (b) Until S4 fixes `<id>`, a test build MUST use the id from AMB-94. If no file is present, the effective value MUST be `true` with `reason=the missing file`. (c) A test build MUST NOT ship or write that file itself. | AIR-016, AIR-023, AIR-025. (b) fail-safe under OD-86. (c) proposal. |
| AIR-064 | (a) Build info MUST be the value of the `ro.build.product` property, not `Build.PRODUCT` or any other property. (b) A failed read or an empty value MUST count as unidentified under AIR-020(b). (c) The value MUST appear in the start record. | AIR-020. (a) is a proposal. (b) fail-safe under OD-86. |
| AIR-065 | (a) The Scheduler MUST use a `Handler` timed by `SystemClock.uptimeMillis()`. (b) Reading ages and the 250 ms clear deadline MUST be measured on that same clock. | The S2_GATE port table. (b) proposal. |
| AIR-066 | (a) `RegulationSource` MUST be implemented on the stock regulation service (`com.hkmc.regulation`), using its notifications only. (b) The regulation state MUST be logged under AIR-038 and MUST NOT affect the gate. (c) The receiver MUST NOT call any regulation setter. | AIR-038, AIR-024. The S2_GATE port table. |
| AIR-067 | (a) The gate MUST make zero calls on `MirrorSession` and `VehicleBus`. (b) No code in the app MUST use any type or method on S2_GATE's forbidden list. | The S2_GATE design. Extending the forbidden list from the gate to the whole app is a proposal. |
| AIR-068 | (a) The receiver MUST NOT write anywhere on the unit except `/data/nemesis/logs/airplay-receiver/` and its own app-data directory. (b) It MUST NOT remount anything, set system properties, or change Wi-Fi, hotspot or DHCP settings, and MUST NOT read Wi-Fi configuration or credentials. (c) The manifest MUST request exactly the permissions AMB-99 settles. (d) It MUST NOT start at boot, run a persistent service, schedule alarms, or declare manifest broadcast receivers. | OD-95, OD-109. (c) depends on AMB-99. (d) proposal. |
| AIR-069 | (a) An uncaught exception MUST write a `crash` record with the exception class and the receiver's own stack frames, then end the process. (b) Nothing MUST restart the receiver automatically. It starts again only when the owner launches it. (c) A failure during start MUST leave video blocked, log its cause, and leave the app in a state the owner can exit. | OD-95, AIR-040. (a) to (c) fail-safe under OD-86. What the owner sees: AMB-100. |
| AIR-070 | (a) On stop, `onDestroy` or `exit()`, the receiver MUST do these steps in order: block video, stop accepting connections, end the session, withdraw the mDNS registration, release the decoder, close all six ports, write the end marker. (b) If a step fails, the receiver MUST log it and still run every later step. | Proposal. (b) fail-safe under OD-86. |
| AIR-071 | (a) Each app start MUST begin its log with a start marker that names the app version, the build's git commit, the UxPlay commit, `ro.build.product` and the effective parking flag. (b) Each session MUST log, in order where they occur: connection accepted; `Mirroring initialized successfully` or `Mirroring not initialized at SETUP`; an S3 codec line with the codec and geometry read from the codec-configuration data; `decoder OMX.TCC.avcdec configured`; the first rendered frame; the first frame the gate withheld; session end with its reason. (c) Each app stop MUST end with an end marker that names the stop reason. (d) The S3 codec line replaces UxPlay's `*** codec is` line, which the excluded GStreamer renderer prints. | OD-139, OD-13, OD-17, AIR-028, AIR-029. The marker text: AMB-102. |
| AIR-072 | The protocol library MUST log at the level that produces the UxPlay lines in AIR-071(b) (debug), and all of its output MUST pass through AIR-073's filter. | Debug level is required for those signatures. |
| AIR-073 | (a) The receiver MUST NOT record video frames, screenshots or any other image of the phone's screen. (b) It MUST NOT record the iPhone's name, device ID, MAC address, IP addresses, pairing or session keys, or the requested URLs. (c) Only native records that match an allowlist of known signatures MAY be written. Every other native record MUST be dropped and counted, and the count logged at session end. (d) Any IPv4, IPv6 or MAC pattern left in an allowed record MUST be replaced with `[redacted]` before it is written. (e) It MUST NOT record the hotspot's SSID, password or configuration. (f) It MAY log the device model and the logged iOS version. | AIR-012, AIR-013, AIR-008(a). The allowlist is the fail-safe choice under OD-86. (f): AMB-106. |
| AIR-074 | (a) A read-only stick script MUST copy the receiver's log directory to the stick under `NEMESIS-diag/airplay-receiver/<timestamp>/` and MUST NOT change or delete the originals. (b) A copy that stops part-way MUST be reported as incomplete and never treated as complete. | Proposal, modelled on `receiver-env-probe`. OD-127. The run route: AMB-92. |
| AIR-075 | (a) The S3 evaluator MUST read the copied logs on the PC and keep raw logs under the uncommitted `runs/` folder. Only the verdict and a redacted summary, in the format of the S1 summaries, MUST go to `docs/evidence/`. (b) A log counts as complete only under AIR-028(b), with S3's start and end markers. Every session in an incomplete log MUST be INCONCLUSIVE with `evidence error`. | The `specs/README.md` evidence rules, AIR-028. |
| AIR-076 | Subject to AIR-075(b): (a) A session MUST be GO when the gate permitted video, the S3 codec line shows H.264, `decoder OMX.TCC.avcdec configured` was logged, a first frame was rendered, and the owner's note says the picture appeared on the unit's screen. (b) It MUST be NO-GO when an iPhone connected and any of these happened: the decoder was unavailable, or errored before the first rendered frame; the stream was HEVC; `Mirroring not initialized at SETUP` was logged; or frames were rendered but the owner's note says no picture appeared. (c) It MUST be INCONCLUSIVE, with the reason, when no iPhone connected, the gate never permitted video, or the owner's note is missing. (d) The run verdict MUST be derived from the session verdicts by S1's rule (AIR-010). | OD-12, OD-13, OD-139, AIR-010, AIR-011. The owner's note: AMB-103. Port and advertising failures: AMB-104. |
| AIR-077 | (a) S3 results MUST state tier `unit`, the firmware build, the iPhone model, the exact iOS version entered by the owner, and the UxPlay commit. (b) A unit GO MUST establish only video on that build with that iPhone, with CarPlay disconnected. It establishes nothing about audio, CarPlay coexistence (S5), other builds or the HUD. (c) `@offline` and `@host` passes MUST NOT be reported as unit evidence. | OD-04, OD-11, OD-138, AIR-014. |
| AIR-078 | (a) S3 test builds MUST reach the unit as a signed APK staged on the owner's USB stick, and MUST NOT be published. (b) Installing and starting them MUST use an existing NEMESIS or Android route the owner chooses, without building S4's package. (c) Uninstalling the APK MUST remove the receiver completely, leaving only the log directory. (d) A failed install MUST end the run, with the route's own output kept on the stick. | OD-127, OD-95, OD-109. The route: AMB-92. |
| AIR-079 | (a) S3 runs MUST be done parked, with CarPlay disconnected and the iPhone joined to the unit's hotspot. (b) At start, the receiver MUST log `carplay listener present` or `carplay listener absent`, based only on whether a local TCP 7000 listener appears in `/proc/net/tcp`. It MUST NOT connect to that port or log any other line of the file. | OD-76, OD-138, OD-146. (b) proposal. What to do when a listener is present: AMB-105. |
| AIR-080 | (a) The receiver MUST NOT take focus back, relaunch itself or bring itself to the front when another app or the camera takes the screen. The last one started wins. (b) No notice MUST be shown while it is covered. | OD-77, OD-117, OD-120, AIR-041. |
| AIR-081 | The receiver MUST draw only into its own activity window on the main display, and MUST NOT create a `Presentation` or use any other display. | OD-22, AIR-027. |
| AIR-082 | (a) The receiver MUST start only when explicitly launched. (b) It MUST NOT declare a home-screen or launcher entry. | OD-95, OD-109. The S3 launch route: AMB-92. |

## Rationale

- **AIR-042.** OD-141 (`docs/spec/DECISIONS.md:149`) chose UxPlay's library with no GStreamer. S1's GO evidence is for commit 05b0275 (`docs/evidence/20261115-142231-summary.md`, `docs/evidence/UXPLAY_LOG_SIGNATURES.md:1-10`), so pinning to it keeps the PC result and the unit result comparable.
- **AIR-043.** This encodes OD-143 (`DECISIONS.md:151`). Refusing other NDKs keeps the build reproducible.
- **AIR-044.** OD-141 needs the library's dependencies, and OD-142 (`DECISIONS.md:150`) sets the precedent of checksum verification. No decision names the dependency versions, hence AMB-91.
- **AIR-045.** This encodes OD-142 (`DECISIONS.md:150`).
- **AIR-046.** This encodes OD-144 (`DECISIONS.md:152`), OD-131 and OD-132 (`DECISIONS.md:139-140`). Clause (c) protects OD-66's plain-Java gate (`DECISIONS.md:74`).
- **AIR-047.** This encodes OD-145 (`DECISIONS.md:153`). Using a throwaway key in AT-47 means nobody handles the owner's passwords.
- **AIR-048.** This encodes OD-76 (`DECISIONS.md:84`). The coexist probe shows that plain `-p` clashes with the unit's services and that a fixed `-p n` avoids it (`docs/evidence/COEXIST_PROBE_FINDINGS.md:26-34`).
- **AIR-049.** OD-76 forbids TCP 7000 and DiPO's ports even with CarPlay off (`DECISIONS.md:84`). DiPO's ports are listed at `COEXIST_PROBE_FINDINGS.md:18-20`. DiPO's random high ports are not mapped (`:38-43`), so (b) forbids explicit binds only.
- **AIR-050.** OD-76 requires advertising through `mdnsd` under a distinct name (`DECISIONS.md:84`). `mdnsd` holds UDP 5353 (`COEXIST_PROBE_FINDINGS.md:17`), and TCP 5353 belongs to another service (`:16`). UxPlay ships its own mDNS, and `-DUSE_DNS_SD=1` switches it to `dns_sd` (`docs/evidence/S1_PC_FACTS.md:28-29`).
- **AIR-051.** This encodes OD-92 (`DECISIONS.md:100`). The unit has one 1920x720 display at 60 fps (`docs/evidence/HUD_VIDEO_FINDINGS.md:55`).
- **AIR-052.** UxPlay sends HEVC only with `-h265` (`S1_PC_FACTS.md:32`). The unit has no HEVC decoder, and avcdec is its H.264 decoder (`S1_PC_FACTS.md:38-39`). The HEVC refusal signature is at `UXPLAY_LOG_SIGNATURES.md:16`.
- **AIR-053.** This encodes OD-93 (`DECISIONS.md:101`).
- **AIR-054.** OD-139 makes this milestone video only, and OD-94 makes audio the next milestone (`DECISIONS.md:147`, `:102`). AIR-022 (`docs/spec/REQUIREMENTS.md:32`) still forbids the gate from touching audio.
- **AIR-055.** OD-141 puts MediaCodec on the Java side (`DECISIONS.md:149`). A narrow boundary keeps every vehicle and display call in Java, where the S2 static scans can see it (`docs/design/S2_GATE.md:30-33`).

## Reversibility and safety

| Requirement | What it installs or changes | How it is undone |
|---|---|---|
| AIR-045 | Installs the SDK under `C:\Android` on this PC. Nothing else on the PC changes. | Delete `C:\Android`. |
| AIR-043, AIR-044 | Put the NDK r25c and the dependency source archives on this PC; the build output stays in the Gradle build directories. | Delete the NDK folder; `./gradlew clean`. |
| AIR-047 | Puts a signing key in the owner's user profile and a git-ignored local file in the checkout. | Deleting the key makes later builds unable to update an installed copy, which then has to be uninstalled first. Before deleting it, the owner should decide whether the same key will sign S4. |
| AIR-078 | On the unit: the APK under `/data/app`, its data under `/data/data`, and the package-manager record. Nothing changes in `/system`. | Uninstall the APK. A half-done install is left to the install route's own rollback (AMB-92). The route has not been tested, so this is not verified. |
| AIR-062 | On the unit: `/data/nemesis/logs/airplay-receiver/`, at most 5 MiB. | Delete the directory. Its creation and owner are AMB-93. |
| AIR-048, AIR-050 | At run time only: listeners on 35000–35002 and an `mdnsd` registration. | Both go away at stop (AIR-070). On process death the ports close. Whether `mdnsd` drops the registration when the client socket closes is not verified. |
| AIR-074 | On the stick: copies of the logs. | Delete them. On the PC, raw logs go under the uncommitted `runs/` folder. |

Vehicle safety:

- Video is gated from the first build, and every edge case blocks video (AIR-057 to AIR-064).
- Vehicle access is read-only, and the BCM call that requests data from the MICOM is never used (AIR-058(b)).
- No new driving or gear-movement test is added. Movement is covered only by the existing AT-41 `@unit` block, under OD-130.
- DiPO, the hotspot, `mdnsd` and `dnsmasq` are never touched (AIR-049(c)), so CarPlay should be unaffected. That holds only by construction and is not tested with CarPlay on, which is S5.

## Not verified

- Every statement below comes from general knowledge, not repository evidence. The `receiver-env-probe` results (hotspot, `mdnsd` socket, codec list) are not yet in `docs/evidence/`.
- **UxPlay library.**
  - Whether the protocol library builds and runs without GStreamer at API 19 with NDK r25c.
  - Its callback API for H.264 data and codec configuration.
  - Whether it uses functions that API 19's bionic lacks, such as `getifaddrs`.
  - How the library takes a base port, given that `-p`, `-n`, `-h265` and the other flags in `UXPLAY_LOG_SIGNATURES.md:47-50` are `uxplay.cpp` command-line flags.
  - Whether the library itself logs addresses or identifiers anywhere besides the excluded `uxplay.cpp:2767` line.
  - I assumed the `raop_*` signature files are part of the library.
- **Dependencies.** Whether the chosen crypto and plist library versions build for API 19 armeabi-v7a.
- **`mdnsd`.** Whether UxPlay's `dns_sd` path works against Android 4.4's `mdnsd` and its client library. Whether a registration is dropped when its client dies.
- **MediaCodec on 4.4 with the TCC decoder.**
  - Surface output, `releaseOutputBuffer(index, false)`, and clearing the Surface within 250 ms.
  - Whether `createByCodecName` works for a name missing from `media_codecs.xml`.
- **Manifest and permissions.**
  - Whether `TYPE_TOAST` works without `SYSTEM_ALERT_WINDOW` on this build.
  - Whether `INTERNET` is needed to listen.
  - Whether `automotive` needs `uses-library`.
- **Properties and time.**
  - That `Build.PRODUCT` reads a different property than `ro.build.product`.
  - How the hidden or `getprop` route to `ro.build.product` behaves.
  - Whether `uptimeMillis` stops during unit sleep, and what that does to reading ages after resume.
- **Crash restart.** Whether Android 4.4's ActivityManager relaunches the activity after a crash (AIR-069(b)).
- **Installing self-signed APKs.** The hmg_nemesis project docs, which are outside this stage root, describe `pm` rejecting non-allowlisted signers while `sys.boot_completed` is `1`. That matters for AMB-92 and is not confirmed in this repository's evidence.
- **Tier tags.** I used `@host` for checks on real build outputs on this PC, and `@offline` for synthetic fixtures and static scans. That is my reading of `specs/README.md`'s tags.
