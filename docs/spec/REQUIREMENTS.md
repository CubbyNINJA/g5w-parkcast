# Requirements

Requirement rows (`AIR-nnn`) and their acceptance tests (`AT-nn`). Rows are drafted by Astra
(`docs/spec/reviews/ASTRA_REQUIREMENTS_*.md`) from the owner decisions in `DECISIONS.md`, and
copied here with any wording change noted. Open questions stay in `AMBIGUITY_REGISTER.md`.

## Requirements

| ID | Requirement | Decision or proposal |
|---|---|---|
| AIR-001 | Before building, the build procedure MUST check the MSYS2 UCRT64 environment, required build tools and packages, GStreamer, and an available H.264 decoder. Missing prerequisites MUST be named and MUST prevent the build from starting. | OD-05; S1 request. Exact dependency set requires validation against the selected revision. |
| AIR-002 | (a) The procedure MUST build UxPlay 1.74 from the upstream `master` commit selected at build time, record its full commit identifier, and pin subsequent repetitions of that build procedure to that commit. Source and build trees MUST remain outside version control. (b) Provenance MUST record the commit, dependency versions, build commands/configuration, executable path and executable hash sufficiently to repeat the procedure. (c) A failed build MUST be reported and MUST NOT make a partial or previous executable appear to be its successful output. (d) If the selected `master` commit does not identify UxPlay 1.74, the procedure MUST stop before building and ask the owner. | OD-05, OD-14. If upstream `master` no longer identifies UxPlay 1.74, the version/revision conflict requires an owner decision. Bit-for-bit reproducibility is not established. OD-20. |
| AIR-003 | Before creating a run’s firewall rule, the runner MUST detect and remove leftover rules attributable to this runner. It MUST preserve unrelated rules. If stale-rule removal fails, it MUST identify the remaining rule and stop before launching UxPlay. | S1 request; ownership identification and fail-before-launch behavior are draft operational details. |
| AIR-004 | For a test run, the runner MUST create a Windows Firewall inbound allow rule restricted to the absolute path of that run’s built `uxplay.exe`, effective on this PC’s active network profile. Failure to establish the rule MUST prevent receiver launch and enter cleanup. | OD-05; S1 request. PC evidence records a Public profile. |
| AIR-005 | The runner MUST remove its temporary firewall rule after normal completion, timeout, startup/run failure or catchable interruption. It MUST verify removal. Failed cleanup MUST report the residual rule identifier and executable path without claiming cleanup succeeded. Rules surviving an uncatchable termination MUST be handled by AIR-003 on the next invocation. | OD-05; S1 request. Immediate cleanup cannot be guaranteed after forced termination or power loss. |
| AIR-006 | The runner MUST launch the verified build with HEVC disabled, advertising `1920×720` at `60 fps` with receiver name `HU-Test`. It MUST record the effective launch configuration and capture UxPlay’s diagnostic output to the run’s log. Failure to start UxPlay or establish log capture MUST be reported and enter cleanup. | OD-04/05, OD-14; S1 configuration. Tests AMB-02 without settling product-wide AMB-04. |
| AIR-007 | (a) Once launched, the runner MUST tell the owner how to select `HU-Test` through iPhone Screen Mirroring and wait for the test. (b) The timeout MUST be 10 minutes measured from receiver launch; connection and video-start events MUST NOT restart that timer. The owner MUST be able to end the test earlier. (c) At owner termination or timeout, the runner MUST stop the launched UxPlay process, then perform firewall cleanup. It MUST record the termination reason and report any process it cannot stop. | OD-06, OD-08, OD-14. |
| AIR-008 | (a) The analyser MUST report separately: evidence of an iPhone connection; mirroring video starting; observed video codec; observed stream resolution; logged audio format; and client model and iOS version when logged. It MUST distinguish a HEVC request from an observed HEVC stream and the advertised display size from the observed stream size. (b) S1 MUST record only the logged audio format as its audio-format evidence and MUST retain the owner’s note about whether sound played. That note MUST NOT change any session or run verdict. | OD-10; S1 request. AMB-06’s head-unit audio choices remain open. |
| AIR-009 | (a) The analyser MUST associate observations with their source log lines and session where identifiable. Missing or unrecognised fields MUST be reported as unknown, without substituting advertised capabilities or expected values. (b) An unreadable or incomplete log, or a log that does not identify the codec, MUST produce INCONCLUSIVE with the reason `evidence error` and the specific limitation named. Such evidence MUST NOT establish GO. (c) A run whose log as a whole is incomplete or partly unreadable MUST be INCONCLUSIVE with the reason `evidence error`, even when one session in it is complete and would be GO. | OD-13; S1 evidence-integrity requirements. Interaction between a run-wide log error and a separately complete GO session under OD-12 remains open. OD-17. |
| AIR-010 | (a) The evaluator MUST assign and list a verdict for every session. Subject to AIR-009 and sufficient, unambiguous evidence, it MUST report GO when an iPhone’s ordinary Screen Mirroring video stream starts using H.264; NO-GO when an iPhone connected but no H.264 mirroring stream started, or it requested HEVC; and INCONCLUSIVE when no iPhone connected. Connection alone, audio-only playback or advertised H.264 capability MUST NOT establish GO. (b) The run MUST be GO if any complete session is GO, with every session’s verdict listed. (c) A YouTube check MUST be recorded as an extra observation only and MUST NOT change any session or run verdict. The owner’s sound-playback note MUST NOT change either verdict. (d) When no session is GO and at least one is NO-GO, the run MUST be NO-GO. (e) A session that requests HEVC and then starts H.264 mirroring MUST be GO, with the HEVC request noted in its reason. | OD-09, OD-10, OD-12, OD-13. AMB-02 remains empirical. Unspecified aggregation and conflicting-evidence cases are listed below; no precedence is invented. OD-18, OD-19. |
| AIR-011 | (a) Every verdict MUST include its reason and references to supporting log lines where available. Unreadable or missing evidence MUST be identified without fabricating references. (b) An absence-based verdict MUST identify the examined log extent and observation endpoint. (c) The run record MUST identify receiver-launch time, the timeout deadline 10 minutes later, and the actual observation endpoint and termination reason, including an earlier owner termination. | OD-08, OD-13; existing provenance requirement. |
| AIR-012 | (a) The run MUST retain its log, analyser report, session verdicts, run verdict, and the owner’s iPhone’s exact iOS version and build under uncommitted `runs/`. S1 targets the owner’s iPhone running iOS 27; the record MUST preserve the exact tested version rather than substitute the major version alone. (b) If the log lacks the iOS version, the runner MUST ask the owner to type it in and MUST mark the supplied value `owner-entered` in the private run record. Required version/build evidence that remains unavailable MUST be identified as missing. (c) Only the verdict and a redacted summary MAY be copied into `docs/evidence/`; raw client names and addresses MUST remain outside committed evidence. (d) The owner-entered value MUST be the full iOS version including its build number, as shown in Settings > General > About. | OD-11, OD-12, OD-15; `specs/README.md`. AMB-03 is decided for S1 only. Collection of a missing build when the log contains a version remains open. OD-21. |
| AIR-013 | S1 MUST NOT record video frames, screenshots, screen-content recordings or other artifacts showing the phone’s screen contents. | S1 request; `specs/README.md` evidence rules. |
| AIR-014 | Results MUST identify their evidence tier. Synthetic fixture results MUST NOT be presented as proof of iPhone compatibility. A PC GO MUST establish only the tested PC/iPhone configuration, without asserting head-unit decoding, networking or playback success. | OD-04; tier rules; AMB-02. No head-unit behavior is tested in S1. |
| AIR-015 | The `Sources/airplay-receiver/` tests MUST use Gherkin and pytest-bdd from the project’s own `.venv`. The hmg_nemesis main suite MUST remain stdlib Python plus pytest. The Gherkin exception MUST apply only to `Sources/airplay-receiver/`. | OD-03, OD-07; confirms the approved process exception. |

## Acceptance tests

| ID | Requirements | Criteria |
|---|---|---|
| AT-01 | AIR-001 | **`@offline`:** Synthetic prerequisite inventories cover complete prerequisites, each missing prerequisite and missing H.264 decoder; failures identify the missing item and prevent build invocation. **`@pc`:** Save the actual UCRT64 prerequisite inventory and decoder inspection result before the build; missing prerequisites block it. |
| AT-02 | AIR-002 | **`@offline`:** Synthetic source-selection and build records prove the build-time upstream `master` commit is recorded and pinned; later movement of `master` does not change a repeated build’s revision. Failed or stale outputs cannot be selected as successful results. **`@pc`:** Retain source-selection evidence and complete build provenance. Repeat the procedure from a clean directory at the recorded commit; retain both build results and executable hashes. Source/build trees remain outside version control. Hash equality is not required. A `master`/1.74 mismatch remains unresolved, not silently substituted. |
| AT-03 | AIR-003 | **`@offline`:** Synthetic firewall inventories include runner-owned stale rules, unrelated rules and removal failure; only owned rules are targeted and failure blocks launch. **`@pc`:** A deliberately retained runner-owned test rule is detected and removed before the next run, with before/after rule evidence. |
| AT-04 | AIR-004 | **`@offline`:** Synthetic rule-creation failure prevents launch and triggers cleanup. **`@pc`:** Firewall inspection proves the rule is inbound, allows only the selected executable path and applies to the active Public profile; retain its identifier and properties. |
| AT-05 | AIR-005 | **`@offline`:** Simulated normal exit, timeout, startup failure, runtime failure and catchable interruption all invoke and verify removal; simulated removal failure reports the residual rule. **`@pc`:** Before/after firewall inspection confirms removal after normal completion, cancellation and an induced run failure. A surviving rule is reported as cleanup failure. |
| AT-06 | AIR-006 | **`@offline`:** Synthetic launch cases assert the verified executable, exact name `HU-Test`, HEVC disabled, `1920×720@60`, log capture, and cleanup on launch/capture failure. **`@pc`:** Retain the effective command/configuration and startup log, checked against the pinned revision’s option semantics, including the receiver name. |
| AT-07 | AIR-007 | **`@offline`:** Controlled-clock fixtures prove timeout at launch plus 600 seconds, including delayed connection and reconnection without timer reset. Earlier owner termination stops the process and triggers cleanup. Stop failures identify the residual process. **`@pc`:** On the wired-PC/home-Wi-Fi arrangement, verify the Screen Mirroring prompt and process termination for early owner completion and timeout; retain launch/end times, termination reasons and process checks. |
| AT-08 | AIR-008 | **`@offline`:** Fixtures cover H.264 mirroring, HEVC request versus stream, connection without video, audio-only activity, advertised versus observed size, and present/absent metadata. Logged audio formats are preserved; absent formats remain unknown. Owner sound notes are stored separately, and changing only that note leaves session and run verdicts unchanged. **`@pc`:** Compare parsed observations with the saved log and retain the owner’s sound-playback note without treating it as measured format evidence or a verdict criterion. |
| AT-09 | AIR-009 | **`@offline`:** Fixtures cover source-line/session attribution, unknown fields, unreadable input, incomplete input and unidentified codec. Each evidence-error case produces INCONCLUSIVE, the exact reason `evidence error`, and its named limitation; none produces GO, including a truncated log containing an apparent H.264-start line. Missing optional metadata is not substituted with expected values. The combined complete-session/run-error boundary awaits the decision below. |
| AT-10 | AIR-010 | **`@offline`:** Sufficient, unambiguous session fixtures yield GO for ordinary H.264 Screen Mirroring, NO-GO for identified-codec cases meeting the existing failure criteria, and INCONCLUSIVE for no connection. Unidentified-codec cases instead use AIR-009’s evidence-error reason. Capability-only and audio-only fixtures never yield GO. Error-free multi-session fixtures prove a complete GO session makes the run GO regardless of session order, with every session verdict listed. Changing only a YouTube observation or sound note leaves both verdict levels unchanged. **`@pc`:** Retain all session verdicts and the run verdict with supporting evidence. A valid NO-GO or INCONCLUSIVE can pass evaluator acceptance; only a valid GO passes the H.264 feasibility gate. Unresolved combinations below have no invented expected verdict. |
| AT-11 | AIR-011 | **`@offline`:** Verdict fixtures retain reasons and valid available source references; unreadable evidence never receives invented line references. Absence-based conclusions identify examined extent and endpoint. Controlled timestamps prove a deadline 600 seconds after launch and correctly record earlier owner termination. **`@pc`:** Verify saved references against retained evidence and verify launch time, timeout deadline, actual endpoint and termination reason. |
| AT-12 | AIR-012 | **`@offline`:** Synthetic records preserve exact iOS version/build values. A missing logged version causes an owner prompt, and the response is retained with the exact marker `owner-entered`. Missing required values remain explicitly missing. Artifact fixtures retain all session verdicts and the run verdict; redaction excludes client names and addresses from published summaries. **`@pc`:** Inspect the private run bundle and version-control exclusions; verify the exact tested iOS 27 version/build and its provenance. If required version/build evidence remains missing, evidence acceptance is incomplete. |
| AT-13 | AIR-013 | **`@offline`:** Synthetic recording requests/configurations cannot enable screen-content capture. **`@pc`:** Inspect the effective capture configuration and produced artifacts; no frame dump, screenshot or screen-content recording is produced. |
| AT-14 | AIR-014 | **`@offline`:** Synthetic reports retain their fixture tier and cannot claim actual iPhone or unit verification. **`@pc`:** The final summary identifies the tested build, PC/iPhone configuration and iOS version, and states that head-unit behavior remains unverified. |
| AT-15 | AIR-015 | **`@offline`:** Synthetic suite-layout and environment fixtures distinguish the AirPlay project’s Gherkin/pytest-bdd `.venv` from the main stdlib-plus-pytest suite and reject extending the exception outside the AirPlay project. **`@pc`:** Retain the actual interpreter/environment and test-collection evidence showing the AirPlay suite uses its own `.venv`; verify the main suite retains its specified framework boundary. |
