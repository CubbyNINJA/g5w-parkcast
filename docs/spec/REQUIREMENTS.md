# Requirements

Requirement rows (`AIR-nnn`) and their acceptance tests (`AT-nn`). Rows are drafted by Astra
(`docs/spec/reviews/ASTRA_REQUIREMENTS_*.md`) from the owner decisions in `DECISIONS.md`, and
copied here with any wording change noted. Open questions stay in `AMBIGUITY_REGISTER.md`.

## Requirements

| ID | Requirement | Decision or proposal |
|---|---|---|
| AIR-001 | Before building, the build procedure MUST check the MSYS2 UCRT64 environment, required build tools and packages, GStreamer, and an available H.264 decoder. Missing prerequisites MUST be named and MUST prevent the build from starting. | OD-05; S1 request. Exact dependency set requires validation against the selected revision. |
| AIR-002 | (a) The procedure MUST build UxPlay 1.74 from the upstream `master` commit selected at build time, record its full commit identifier, and pin subsequent repetitions of that build procedure to that commit. Source and build trees MUST remain outside version control. (b) Provenance MUST record the commit, dependency versions, build commands/configuration, executable path and executable hash sufficiently to repeat the procedure. (c) A failed build MUST be reported and MUST NOT make a partial or previous executable appear to be its successful output. (d) If the selected `master` commit does not identify UxPlay 1.74, the procedure MUST stop before building and ask the owner. | OD-05, OD-14. If upstream `master` no longer identifies UxPlay 1.74, the version/revision conflict requires an owner decision. Bit-for-bit reproducibility is not established. OD-20. |
| AIR-003 | Before creating a run’s firewall rule, the runner MUST detect and remove leftover rules attributable to this runner. It MUST preserve unrelated rules. If stale-rule removal fails, it MUST identify the remaining rule and stop before launching UxPlay. | S1 request; ownership identification and fail-before-launch behavior are draft operational details. |
| AIR-004 | For a test run, the runner MUST create a Windows Firewall inbound allow rule restricted to the absolute path of that run’s built `uxplay.exe`, effective on this PC’s active network profile. Failure to establish the rule MUST prevent receiver launch and enter cleanup. | OD-05; S1 request. PC evidence records a Public profile. |
| AIR-005 | The runner MUST remove its temporary firewall rule after normal completion, timeout, startup/run failure or catchable interruption. It MUST verify removal. Failed cleanup MUST report the residual rule identifier and executable path without claiming cleanup succeeded. Rules surviving an uncatchable termination MUST be handled by AIR-003 on the next invocation. | OD-05; S1 request. Immediate cleanup cannot be guaranteed after forced termination or power loss. |
| AIR-006 | The runner MUST launch the verified build with HEVC disabled, advertising `1920×720` at `60 fps` with receiver name `HU-Test`. It MUST record the effective launch configuration and capture UxPlay’s diagnostic output to the run’s log. Failure to start UxPlay or establish log capture MUST be reported and enter cleanup. | OD-04/05, OD-14; S1 configuration. Tests AMB-02 without settling product-wide AMB-04. |
| AIR-007 | (a) Once launched, the runner MUST tell the owner how to select `HU-Test` through iPhone Screen Mirroring and wait for the test. (b) The timeout MUST be 10 minutes measured from receiver launch; connection and video-start events MUST NOT restart that timer. The owner MUST be able to end the test earlier. (c) At owner termination or timeout, the runner MUST stop the launched UxPlay process, then perform firewall cleanup. It MUST record the termination reason and report any process it cannot stop. | OD-06, OD-08, OD-14. |
| AIR-008 | (a) The analyser MUST report separately: evidence of an iPhone connection; mirroring video starting; observed video codec; observed stream resolution; logged audio format; and client model and iOS version when logged. It MUST distinguish a HEVC request from an observed HEVC stream and the advertised display size from the observed stream size. (b) S1 MUST record only the logged audio format as its audio-format evidence and MUST retain the owner’s note about whether sound played. That note MUST NOT change any session or run verdict. | OD-10; S1 request. AMB-06’s head-unit audio choices remain open. |
| AIR-009 | (a) The analyser MUST associate observations with their source log lines and session where identifiable. Missing or unrecognised fields MUST be reported as unknown, without substituting advertised capabilities or expected values. (b) A session in which a mirroring video stream arrived (AIR-029(b)) but no `*** codec is` line identifies its codec, and which shows no HEVC refusal (AIR-029(d)), MUST be INCONCLUSIVE with the reason `evidence error` and the limitation `codec not identified`. A session in which no video stream arrived, or whose video was refused as HEVC, keeps its verdict under AIR-010(a), even though no codec is logged. Such evidence MUST NOT establish GO. (c) A run whose log as a whole is incomplete or partly unreadable MUST be INCONCLUSIVE with the reason `evidence error`, even when one session in it is complete and would be GO. | OD-13 as narrowed by OD-25 (stream arrival per AIR-029); OD-17 resolves the interaction between a complete GO session and a run-wide incomplete or partly unreadable log: the run is INCONCLUSIVE with reason `evidence error`. |
| AIR-010 | (a) The evaluator MUST assign and list a verdict for every session. Subject to AIR-009 and sufficient, unambiguous evidence, it MUST report GO when an iPhone’s ordinary Screen Mirroring video stream starts using H.264; NO-GO when an iPhone connected but no H.264 mirroring stream started, or it requested HEVC; and INCONCLUSIVE when no iPhone connected. Connection alone, audio-only playback or advertised H.264 capability MUST NOT establish GO. (b) Subject to the run-wide evidence-error override in AIR-009(c), the run MUST be GO if any complete session is GO, with every session’s verdict listed. (c) A YouTube check MUST be recorded as an extra observation only and MUST NOT change any session or run verdict. The owner’s sound-playback note MUST NOT change either verdict. (d) Subject to the run-wide evidence-error override in AIR-009(c), when no session is GO and at least one is NO-GO, the run MUST be NO-GO. (e) A session that requests HEVC and then starts H.264 mirroring MUST be GO, with the HEVC request noted in its reason. (f) A run whose sessions are all INCONCLUSIVE MUST be INCONCLUSIVE. A run with no session MUST be INCONCLUSIVE with the reason `no iPhone connected`. | OD-09, OD-10, OD-12, OD-13, OD-17, OD-18, OD-19, OD-25, OD-26. AMB-02 remains empirical. |
| AIR-011 | (a) Every verdict MUST include its reason and references to supporting log lines where available. Unreadable or missing evidence MUST be identified without fabricating references. (b) An absence-based verdict MUST identify the examined log extent and observation endpoint. (c) The run record MUST identify receiver-launch time, the timeout deadline 10 minutes later, and the actual observation endpoint and termination reason, including an earlier owner termination. | OD-08, OD-13; existing provenance requirement. |
| AIR-012 | (a) The run MUST retain its log, analyser report, session verdicts, run verdict, and the owner’s iPhone’s exact iOS version and build under uncommitted `runs/`. S1 targets the owner’s iPhone running iOS 27; the record MUST preserve the exact tested version rather than substitute the major version alone. (b) If either the exact iOS version or its build number is unavailable, the runner MUST ask the owner for the full iOS version including its build number, as shown in Settings > General > About. It MUST retain the supplied value in the private run record with provenance `owner-entered`. Any required version or build value that remains unavailable MUST be identified as missing, and evidence acceptance MUST remain incomplete. (c) Only the verdict and a redacted summary MAY be copied into `docs/evidence/`; raw client names and addresses MUST remain outside committed evidence. (d) The owner-entered value MUST be the full iOS version including its build number, as shown in Settings > General > About. | OD-11, OD-12, OD-15, OD-21; `specs/README.md`. OD-21 requires owner entry of the full version and build when required version/build evidence is unavailable. |
| AIR-013 | S1 MUST NOT record video frames, screenshots, screen-content recordings or other artifacts showing the phone’s screen contents. | S1 request; `specs/README.md` evidence rules. |
| AIR-014 | Results MUST identify their evidence tier. Synthetic fixture results MUST NOT be presented as proof of iPhone compatibility. A PC GO MUST establish only the tested PC/iPhone configuration, without asserting head-unit decoding, networking or playback success. | OD-04; tier rules; AMB-02. No head-unit behavior is tested in S1. |
| AIR-015 | The `Sources/airplay-receiver/` tests MUST use Gherkin and pytest-bdd from the project’s own `.venv`. The hmg_nemesis main suite MUST remain stdlib Python plus pytest. The Gherkin exception MUST apply only to `Sources/airplay-receiver/`. | OD-03, OD-07; confirms the approved process exception. |
| AIR-016 | The package MUST default to requiring Park for mirrored video. It MUST provide a package flag that can disable this parking requirement. | OD-24; flag representation and activation remain AMB-24. |
| AIR-017 | With the parking requirement enabled, the gate MUST initially block mirrored video and MUST permit it only when the current gear signal positively establishes Park on a recognized firmware build. Stationary status or an applied parking brake alone MUST NOT establish Park. | OD-23, OD-24; request for startup and unknown-firmware handling. Firmware recognition and gear mapping remain open. |
| AIR-018 | With the parking requirement enabled, leaving Park MUST immediately prevent further mirrored frames from appearing and remove any already displayed mirrored image, including a frozen last frame. Queued frames MUST NOT restore the image while blocked. | OD-23; explicit request for stopping video at once. Measurable latency remains open. |
| AIR-019 | With the parking requirement enabled, unavailable, erroring or unknown gear information MUST block video, both at startup and after a previously valid Park reading. A previous Park reading MUST NOT override a known signal failure. A restored valid Park reading MAY make video eligible again, subject to AIR-017. | OD-23; explicit failure-path request. Signal freshness and playback-resumption mechanics remain open. |
| AIR-020 | With the parking requirement enabled, an unknown firmware build MUST leave video blocked, even if a returned value resembles Park on another build. This failure MUST NOT be treated as verified Park. | Explicit unknown-firmware request; feasibility firmware gap. Recognition mechanism and supported-build evidence remain open. |
| AIR-021 | When the package flag explicitly disables the parking requirement, the parking gate MUST NOT block mirrored video because of gear state, unavailable/erroring/unknown gear information, or an unknown firmware build. It MUST NOT disable or alter stock restrictions to achieve this. | OD-24; removes this gate’s parking requirement only. |
| AIR-022 | The parking gate MUST NOT mute, stop or disconnect mirrored audio because of any parking-gate state or transition, with the flag enabled or disabled. An existing audio stream MUST remain unaffected by this gate when video becomes blocked. | OD-23, OD-24. Actual audio routing remains AMB-06; this does not promise immunity from unrelated playback failures. |
| AIR-023 | **Proposed:** (a) The flag MUST be `video.require_park` in `package/config/receiver.conf`, installed as `/data/nemesis/apps/<id>/config/receiver.conf`, accepting `true` and `false`. (b) A missing file/key, unreadable configuration or unrecognised value MUST resolve to enabled, rather than preserve an earlier disabled value. (c) The receiver MUST read the installed flag at every app start; a change MUST take effect at the next app start after editing the installed copy or rebuilding and reinstalling the package. It MUST NOT take effect during an already running instance. | **OPEN AMB-24 proposal**, not an owner decision. Exact parsing details and update preservation remain open. |
| AIR-024 | Vehicle-signal access by the gate MUST be read-only: it MAY query status and subscribe to status notifications, but MUST NOT command vehicle behavior, write directly to CAN, change vehicle settings or driver-assistance toggles, modify stock regulation behavior, or spoof regulation events. | Supplied SCOPE exclusions; OD-22. Status-query/subscription IPC is permitted; “read-only” does not prohibit sending a query to the stock service. |
| AIR-025 | At every receiver start, the gate MUST log its effective flag value, whether that value was explicitly read or obtained by fallback, its initial video-gate state, and the reason for that state. A failed configuration read MUST be identified as such, without logging unrelated configuration contents. | Explicit logging request; fallback semantics depend on AMB-24. Log destination and logging-failure behavior remain open. |
| AIR-026 | Each gate-state transition and each effective flag-value transition MUST be logged with the previous and resulting values/states and the reason. A newly applied flag value at restart MUST be recorded as the startup value; if its previous value is unavailable, the log MUST identify that rather than invent it. | Explicit transition-logging request. Record fields are draft operational detail; cross-start history mechanism remains open. |
| AIR-027 | The receiver MUST NOT display mirrored video on the HUD, regardless of the parking flag. Any later HUD feature MUST be text only through channels the stock software already uses and MUST NOT touch driver-assistance display toggles. | OD-22. No HUD feature is introduced by this slice. |
| AIR-028 | (a) The runner MUST write a start marker as the log's first line before UxPlay's output, and, after UxPlay has stopped, an end marker naming the termination reason as its last line. (b) A log is complete only if it is readable UTF-8 text, its first line is the start marker, it contains UxPlay's version banner, its last line is the end marker, and it ends with a newline. (c) Any other log MUST be reported incomplete under AIR-009(c), naming the first limitation that applies, in this order: `unreadable`, `no start marker`, `no UxPlay banner`, `truncated` (no end marker, or no final newline). | **Parent addition** from the S1 coverage review, finding 3; defines OD-13 and OD-17's "incomplete". Marker text is an implementation detail. |
| AIR-029 | (a) Mirroring video started MUST be observed only from a `*** codec is` line in that session, which also gives the codec and the stream geometry. (b) A mirroring video stream arrived when the session shows the `raop_rtp_mirror width_source =` line, which UxPlay logs on receiving the stream's first codec-configuration packet. (c) `Mirroring initialized successfully` and `raop_rtp_mirror accepting client` show only setup and the opened mirror connection; neither MUST be reported as video arriving or starting. (d) A session whose arriving stream was refused with `raop_rtp_mirror: received type 0x01 packet with no payload:` requested HEVC; AIR-009(b) doesn't apply to it. | **Parent addition** from review findings 1 and 2, encoding OD-25. Source: `lib/raop_rtp_mirror.c:243,603,608` and `renderers/video_renderer.c:1077` at 05b0275. |
| AIR-030 | (a) A firewall rule is owned by the runner only if its display name is exactly `NEMESIS-AirPlay-S1` and its program is a `uxplay.exe` under the build root recorded in the build's provenance. (b) Stale-rule removal (AIR-003) MUST remove every owned rule and verify the removal before the run's rule is created. (c) A rule with that name but another program MUST NOT be removed or changed; the runner MUST report it with its program and stop before creating a rule or launching UxPlay. (d) Cleanup MUST remove only the rule this run created; every rule the runner doesn't own MUST be unchanged after the run. (e) Restrictions on what a rule allows (AIR-004) apply to the rules the runner creates. | **Parent addition** from review finding 9; OD-27. |
| AIR-031 | (a) The S1 tools MUST be one command, `python tools/s1.py <command>`, with the commands `check`, `build`, `run`, `analyse`, `evaluate` and `summary`. (b) `--help`, alone or after any command, MUST print usage and exit 0 with no other effect. (c) An unknown command, unknown option or missing required argument MUST exit 2 with usage on stderr, and MUST NOT start a build, change a firewall rule, launch UxPlay, or create or change any file. (d) A missing or unreadable build provenance MUST make `run` exit 1 naming the file, before any firewall change. (e) An output location that can't be written MUST make the command exit 1 naming it, before any firewall change or launch, and leave no partial output file. (f) Any other failure MUST exit 1 with its reason on stderr. A failure after the run's firewall rule is created MUST go through AIR-005 cleanup and report any residual rule or process. A completed command exits 0, whatever its verdict. | **Parent addition** from review finding 13; OD-28, OD-29. |
